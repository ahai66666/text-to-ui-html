# Normalize a static or interactive Demo
Read `references/workflows/normalize-demo-plan.md` before changing page files. Use the existing Workflow → Task → Pattern routing and six resource stages; the four execution phases group work without adding a route.

First run `normalization-plan.mjs init --source <original directory or HTML file> --project <separate output> --task <task>`. It preserves the original, fingerprints source and skill, creates the 17-task plan, derived Markdown/evidence views, and an explicitly unfinished preservation inventory. Inspect the original and refine `demo-preservation.json` before setting inventoryComplete true. Do not invent undefined search/save/submit semantics; record gaps and required user decisions.

On every new model/context or interrupted run, run `normalization-plan.mjs resume --project <output>` and read its current task, decisions, stale results, required files and next action. Resolve blocking decisions; preserve valid results. Update progress at task boundaries and before ending a turn. The JSON plan is authoritative; Markdown and evidence ledger are derived and repaired by resume. Plan commands serialize writes and use atomic replacement. A writer lock left by a killed process must be checked against its recorded PID before removal; never remove an active writer's lock.

Use workflow normalize-demo in stage queries and pass `--normalization-plan <project>/normalization-plan.json --preservation <project>/demo-preservation.json`; carry Blueprint/bindings when available. Stage packs project current plan state and decisions without loading its complete history.

Complete N01–N06 with current evidence before `normalize-demo.mjs --source <original> --project <output> --task <task>`. This wrapper checks source/task, separate paths, fixed page inputs, freshness and prerequisites, then calls the strict generator. Generation success records N07 only; failures record a blocked step. The same project is used for framework and styling checkpoints, not two competing implementations. Generation uses standard paths (page-blueprint.json, page-content-recipes.json, page-bindings.json, styles/page-composition.css, .text-to-ui/context-packet.json).

Keep standard components and Pattern geometry intact. The model edits design inputs, business composition CSS and declared business modules; scripts own generated hosts, modules, copied dependencies and style manifests. Browser-check every preservation item. A build is not behavioral or visual acceptance. Before a repair/regeneration, invalidate the affected task; resume invalidates changed evidence and dependent results. Source/build/browser remain separate. N01–N16 must pass before the formal HTML handoff; it records N17 only after handoff verification. Finish at html-handoff.json; canvas import and Git publication require their own requested scope.
